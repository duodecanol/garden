# Proxmox VE 9.2 — `No valid subscription` 제거

## 요약

`No valid subscription`은 두 종류다.

1. **APT 업데이트 오류**: Enterprise 저장소를 구독 없이 사용해서 발생한다.
2. **Web GUI 로그인 팝업**: 노드에 유효한 구독 키가 없다는 GUI 알림이다.

No-Subscription 저장소로 변경해도 **GUI 팝업은 자동으로 사라지지 않는다**. 팝업까지 없애는 공식적인 방법은 유효한 Proxmox 구독 키를 등록하는 것이다.

## 1. APT Enterprise 저장소 비활성화

Proxmox VE 9는 Debian 13 Trixie 기반이며, 현재 권장 저장소 형식은 Deb822 `.sources` 파일이다.

### GUI

1. **Datacenter → Updates → Repositories** 이동
2. `pve-enterprise` 비활성화
3. **Add → No-Subscription** 선택
4. 저장 후 **Refresh** 실행

### CLI

먼저 기존 Enterprise 파일 이름을 확인한다.

```bash
ls -1 /etc/apt/sources.list.d/
```

기본 설치의 `.sources` 파일을 비활성화하려면:

```bash
mv /etc/apt/sources.list.d/pve-enterprise.sources \
   /etc/apt/sources.list.d/pve-enterprise.sources.disabled
```

`pve-enterprise.sources`가 없다면 기존 `.list` 파일을 확인하고 해당 파일을 비활성화한다. 이미 `pve-no-subscription` 저장소가 있으면 중복으로 추가하지 않는다.

```bash
cat >/etc/apt/sources.list.d/proxmox.sources <<'EOF'
Types: deb
URIs: http://download.proxmox.com/debian/pve
Suites: trixie
Components: pve-no-subscription
Signed-By: /usr/share/keyrings/proxmox-archive-keyring.gpg
EOF
```

반영 및 확인:

```bash
apt update
```

`pve-enterprise` 인증 오류가 없어야 한다.

> Proxmox 공식 문서상 `pve-no-subscription`은 무료로 사용할 수 있지만 Enterprise보다 검증 수준이 낮아 테스트 및 비생산 환경에 적합하다.

## 2. Web GUI 로그인 팝업 숨기기

홈랩에서 팝업만 숨기려는 경우에 한해 GUI JavaScript를 패치한다. 패치 대상은 `proxmox-widget-toolkit` 패키지의 파일이다.

```bash
FILE=/usr/share/javascript/proxmox-widget-toolkit/proxmoxlib.js

cp -a "$FILE" "$FILE.backup.$(date +%Y%m%d-%H%M%S)"

perl -0pi -e \
"s/Ext\\.Msg\\.show\\((?=\\{\\s*title:\\s*gettext\\('No valid subscription'\\))/void(/s" \
"$FILE"

systemctl restart pveproxy
```

브라우저에서 `Ctrl + Shift + R`로 강력 새로고침하거나 시크릿 창으로 다시 로그인한다.

### 복구

패키지 원본으로 되돌리려면:

```bash
apt install --reinstall proxmox-widget-toolkit
systemctl restart pveproxy
```

### 주의사항

- `proxmox-widget-toolkit` 업데이트 시 원본 파일로 덮어써져 팝업이 다시 나타날 수 있다.
- 업데이트 후 패치가 필요한지 확인한다.
- 운영 환경에서는 JavaScript 패치보다 팝업을 유지하거나 구독을 등록하는 편이 안전하다.
- 팝업 자체는 VM/CT 기능을 제한하지 않는다.
- Ceph를 사용 중이면 `ceph.sources`의 Enterprise 저장소도 별도로 확인해야 한다. Ceph 버전은 현재 클러스터 구성에 맞춰야 하므로 무조건 다른 Ceph 버전으로 바꾸지 않는다.
