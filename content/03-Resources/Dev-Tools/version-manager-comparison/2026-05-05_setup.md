# Setup — mise/proto/aqua 격리 비교 환경

## 의도

매니저 3개를 같은 입력으로 굴려 **설계 차이**를 드러낸다. 설치 시간 정밀 측정이 목적이 아니라 (Docker 캐시 때문에 어차피 왜곡됨), 다음을 비교한다:

1. **설정 문법** — `.mise.toml`, `.prototools`, `aqua.yaml`
2. **활성화 메커니즘** — PATH 조작 vs shim vs 단일 `bin/` 디렉터리
3. **디렉터리 인지 스위칭** — root 3.12 / `tools/python/` 3.11
4. **재현성** — 새 셸에서 동일 결과
5. **커버리지 한계** — aqua가 python을 다루지 못한다는 사실 자체가 결과

## "want" 리스트 (모든 매니저 공통)

| Tool | Root | tools/python override |
|---|---|---|
| python | 3.12 | 3.11 |
| go | 1.23 | — |
| bun | 1.1.30 | — |
| terraform | 1.9.0 | — |

## Docker 격리 설계

- 베이스: `ubuntu:24.04` (셋 다 동일)
- 매니저별로 Dockerfile 분리. 같은 매니저 내에서는 install + scenarios.sh가 한 컨테이너에서 끝까지.
- `mise`/`proto`는 python을 소스 빌드하므로 `build-essential` + python-build 의존성 추가. `aqua`는 단일 바이너리만 다루므로 의존성이 가볍다 → 그 자체가 차이점.

## 시나리오 (`scenarios.sh`)

각 컨테이너에서 동일 흐름:

1. 매니저 버전·경로 출력
2. cold install — `time` 으로 측정
3. root에서 active 버전 + `which $tool` 출력
4. `tools/python/`로 cd 후 python 버전 재출력 (오버라이드 검증)
5. 새 `bash -lc`에서 재출력 (활성화 영속성 검증)
6. shim/bin 디렉터리 ls

## 실행

```bash
cd ~/xxDev/version-manager-comparison
./compare.sh           # 세 매니저 모두
./compare.sh mise      # 하나만
```

## aqua + python 처리

aqua는 GitHub Releases의 단일 바이너리만 본다. CPython은 그렇게 배포되지 않으므로 aqua.yaml에서 의도적으로 빠짐. `aqua/tools/python/README.md`에 이유 명시. → 결론에서 "aqua는 런타임 매니저가 아니라 CLI installer"로 정리할 것.
